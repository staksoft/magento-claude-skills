# Hyvä Child Theme Setup & Tailwind Build

You almost never edit the Hyvä default theme directly. You create a **child theme** that
inherits from `Hyva/default` and add your overrides and Tailwind customizations there.

## Theme structure

```
app/design/frontend/Vendor/theme/
├── registration.php
├── theme.xml
├── composer.json            (optional, for distribution)
├── web/
│   ├── tailwind/
│   │   ├── tailwind.config.js
│   │   ├── postcss.config.js
│   │   ├── package.json
│   │   └── tailwind-source.css
│   ├── css/
│   │   └── styles.css        (generated by the Tailwind build — do not edit)
│   └── images/
├── Magento_Theme/
│   └── layout/ templates/
└── etc/view.xml
```

`registration.php`:

```php
<?php
use Magento\Framework\Component\ComponentRegistrar;

ComponentRegistrar::register(
    ComponentRegistrar::THEME,
    'frontend/Vendor/theme',
    __DIR__
);
```

`theme.xml` — the parent is what makes it a Hyvä theme:

```xml
<theme xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:noNamespaceSchemaLocation="urn:magento:framework:Config/etc/theme.xsd">
    <title>Vendor Theme</title>
    <parent>Hyva/default</parent>
</theme>
```

Register and activate:

```bash
bin/magento setup:upgrade
bin/magento config:set design/theme/theme_id <id-from-`theme:list`>   # or Admin: Content > Design > Configuration
```

## The Tailwind build

Hyvä compiles Tailwind at build time (not in the browser). The build lives in
`web/tailwind/`. A child theme's `tailwind.config.js` extends the parent's:

```js
const config = require('@hyva-themes/hyva-modules').hyvaModules(
  require('../../../../../../vendor/hyva-themes/magento2-default-theme/web/tailwind/tailwind.config.js')
);

module.exports = {
  ...config,
  content: [
    '../../**/*.phtml',
    '../../**/*.html',
    // scan modules that emit Hyvä markup so their classes aren't purged:
    '../../../../../../app/code/**/view/frontend/**/*.phtml',
    '../../../../../../vendor/hyva-themes/**/templates/**/*.phtml',
  ],
  theme: {
    extend: {
      colors: { brand: { DEFAULT: '#0d6efd' } },
    },
  },
};
```

The `content` (purge) globs are the #1 gotcha: any `.phtml` that outputs Tailwind classes but
is **not** matched is purged from the final CSS, so its styles silently vanish in production.
When a class "works locally but not after deploy," check the content globs first.

Build commands:

```bash
cd app/design/frontend/Vendor/theme/web/tailwind
npm ci                 # first time
npm run build          # one-off production build → ../css/styles.css
npm run watch          # rebuild on change during development
```

In production you still run `bin/magento setup:static-content:deploy -f` to publish the
compiled `styles.css` to `pub/static`.

## Coexisting with Luma

Hyvä is set per **store view**, so a multi-store install can run Hyvä on one store and Luma on
another. The theme switch is just the `design/theme/theme_id` config at the store-view scope.
